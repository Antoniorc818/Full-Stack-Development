Artifact Description

The artifact for this milestone is the data layer of Travlr Getaways: the Trip and User Mongoose schemas, the trip CRUD controllers, and the MongoDB connection setup, which were largely unchanged from the original CS 465 version before this enhancement.

Justification for Inclusion

The original database layer validated almost nothing beyond checking that a field existed, had no indexes to support the queries the app actually runs, couldn't answer any aggregate business questions, and had a MongoDB connection string hardcoded directly in source.

// before: bare required-field checks only perPerson: { type: Number, required: true, min: 0 } // after: real constraints perPerson: { type: Number, required: true, min: [0, 'Price per person cannot be negative'], max: [100000, 'Price per person exceeds the allowed maximum'] } // added: compound index matching actual query patterns tripSchema.index({ resort: 1, start: 1 });

Four changes: real validation (length/pattern checks on code, name, resort, description; a regex on length; min/max bounds on price); a compound index on resort and start, the two fields the admin SPA's search and the new report both query against; an aggregation pipeline that groups trips by resort and computes trip count, average price, and average length, exposed through /api/trips/reports/by-resort and a small Angular reporting page; and moving the MongoDB connection string into environment configuration, the same pattern already used for the JWT secret.

Course Outcomes

This aligns with Course Outcome 4, using well-founded tools and techniques to implement a database solution that delivers real value, and Course Outcome 5, building a security mindset around data and resources.

Reflection

The trickiest part was the aggregation pipeline's average trip length: length is stored as free text like "5 days" rather than a number, so I couldn't $avg it directly. I added a stage that splits the string on the space and converts the first piece to an integer using $split and $convert before grouping — a reminder that schema decisions made early have downstream costs when you want to do math on that field later.

I also ran into a build issue unrelated to the database work while wiring up the new reports page: the Angular root component file had the wrong content in it, and the app's router and forms providers weren't being registered at bootstrap. Neither was caused by this enhancement, but the reports page couldn't render without both fixed, so I corrected them as part of this milestone.
